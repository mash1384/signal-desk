# Delfona 요약 시스템 연구 — 우리 데이터로 '여기 아니면 안 되는' 이유 만들기

작성 2026-10-17. 근거: 경쟁 서비스 조사, 지난 24~72시간 실데이터 분석(아래 숫자는 모두 실측).

## 0. 결론

요약을 '문장 몇 개'로 만드는 한, 어떤 모델을 써도 기사 다시 쓰기에 그친다. 우리가 이길 수 있는 단위는 **이야기(줄기, thread)** 다.
여러 언어 채널의 속보를 같은 소식끼리 묶고(이미 함), 그 소식들을 다시 **날을 넘어 이어지는 이야기**로 묶어,
이야기마다 "무엇이 새로 일어났나 · 왜 중요한가 · 다음은 무엇인가 · 며칠째인가"를 계속 갱신한다.
사용자는 **이야기를 팔로우**하고, 다시 들어오면 **"다녀온 사이 무엇이 바뀌었나"** 만 본다.

이 구조가 만드는 잠금(lock-in):
1. **기록**: 이야기의 처음부터의 타임라인은 우리가 계속 모아 온 사람만 가진다(시간이 갈수록 커지는 해자).
2. **개인 상태**: 팔로우한 이야기·코인, 마지막 방문 이후 변화 — 다른 데로 옮기면 사라진다.
3. **시차**: 영어·중국어 채널이 한국 채널보다 먼저 낸 소식을 한국어로 먼저 — 분 단위로 측정 가능.
4. **신뢰 장부**: 우리가 "다음에 볼 것"으로 꼽은 일이 실제로 일어났는지 공개 기록.

## 3. 사용자와 할 일

| 사람 | 하고 싶은 것 | 우리가 줄 것 |
|---|---|---|
| 단타·뉴스 트레이더 | 남보다 먼저, 무엇이 큰지 | 라이브 + 시차 배지 + 확산 중 + 큰 소식 알림 |

## 4. 시스템 설계 — 5단 뉴스 그래프

```
L0 줄(post)     채널 글 1개. 판정·번역(이미 있음)
L1 소식(story)  같은 소식 묶음. 첫 보도 시각·언어별 시각·보도 수(이미 있음 + 시차 계산 추가)
L2 이야기(thread) 날을 넘어 이어지는 소식들. 상태: 새로 시작 · 전개 중 · 고조 · 잠잠. 등장 주체(회사·코인·기관)
L3 테마          크립토 · 나스닥 · 경제 · AI — 오늘의 이야기 지도
L4 나(me)        팔로우한 이야기·코인, 마지막 방문 시각
```

### 이야기 엔진(L2)
- 새 소식이 들어오면: 가장 가까운 열린 이야기에 붙인다(의미 유사도 + 같은 주체). 없으면 새 이야기.
  원형의 문제(한 덩어리로 211건이 엉킴)는 '평균 연결 + 주체 일치 필수 + 크기 상한'으로 막는다.
- 상태는 프로그램이 정한다: 지난 6시간 새 소식 수, 보도 수, 세기 → 새로 시작 / 전개 중 / 고조 / 잠잠(48시간 무소식이면 닫음).
- 이야기 장부(DB 표): id, 제목, 주체, 처음 본 시각, 마지막 갱신, 상태, 소식 id 목록, 요약 판본들.

### AI 요약 로직 — '사실표 → 제한된 글쓰기 → 검사'
1. **사실표**(프로그램): 이야기의 새 소식들, 이전 요약, 며칠째, 보도 수·언어별 첫 시각, 관련 일정.
2. **글쓰기**(Gemma, 이야기 하나에 몇 초): 무엇(새 전개) · 왜 중요 · 다음 · 제목.
   문장마다 근거 소식 id 필수. 바뀐 이야기만 다시 쓴다(3시간마다 전부가 아니라 새 소식이 붙을 때마다 조금씩).
3. **검사**(프로그램): 자료에 없는 숫자, 시세 인과 단정, 매매 권유, 근거 없는 문장 → 빼고 다시 쓰게, 끝내 안 되면 사실표의 틀 문장으로.
4. **판본 보관**: 요약이 어떻게 바뀌어 왔는지가 그대로 이야기의 타임라인이 된다.

### 요약에서 나오는 화면들
| 화면 | 내용 | 왜 다시 오게 하나 |
|---|---|---|
| 다녀온 사이 | 마지막 방문 이후: 팔로우한 이야기의 새 전개, 새로 시작된 큰 이야기, 놓친 큰 소식 | 들어오자마자 '나한테 필요한 것만' |
| 이야기 카드 | 제목 · 며칠째 · 오늘 새 전개 · 왜 중요 · 다음 · 타임라인 | 연재처럼 다음 회가 궁금 |
| 한국 시차 렌즈 | "해외 47분 먼저", "중국어 채널만" 배지, 아직 한국에 없는 큰 소식 | 우리에게 오면 먼저 안다 |
| 일정 앞뒤 | 발표 30분 전: 관련 이야기·과거 반응 크기 / 발표 직후: 실제 수치와 예상 | 정해진 시각에 오는 습관 |
| 신뢰 장부 | 어제 '다음에 볼 것' 중 실제로 일어난 것 | 믿을 이유가 쌓임 |
| 테마 페이지 | 그 테마의 이야기 지도 + 숫자 신호 + 자산 | 깊게 볼 곳 |

## 5. 습관과 잠금

- **정해진 시각**: 아침 7:30(밤사이 미국장·해외) · 점심 12:30 · 밤 22:00(미국장 개장 전) — 한국 생활 시간에 맞춘 이야기 브리핑.
- **알림은 텔레그램 봇**: 국내 크립토 투자자는 이미 텔레그램에 있다. 이야기·코인 팔로우 → 새 전개가 생길 때만 알림(소음 없이).
- **로그인 없이 시작**: 팔로우·마지막 방문은 브라우저에 저장 → 나중에 텔레그램 봇과 연결해 기기를 옮겨도 유지.
- **기록이 해자**: 이야기 페이지는 처음부터의 타임라인을 남긴다. 늦게 온 경쟁자는 과거를 만들 수 없다.

## 6. 유입

- 이야기마다 고정 주소(`/s/호르무즈-해협-기뢰`) — 검색으로 들어올 문이 매일 늘어난다.
- 공유 카드(이미지): "호르무즈 해협 · 4일째 · 오늘 새 전개 2건".
- 우리 텔레그램 채널이 이야기 갱신을 자동으로 올림 → 구독자가 사이트로.
- 주간 정리: 이번 주 가장 큰 이야기 5개(시작 · 전개 · 지금).

## 8. 단계

1. **이야기 엔진**(1~2주): 이야기 장부 · 붙이기 · 상태 · 사실표 · Gemma 글쓰기 · 검사. 테마 페이지 맨 위에 이야기 카드.
2. **다녀온 사이 + 팔로우**(1주): 브라우저 저장, 라이브·테마 첫머리에.
3. **한국 시차 렌즈**(며칠): 소식에 언어별 첫 시각 → 배지, '아직 한국에 없음' 칸. 국내 텔레그램 채널 추가로 비교 정확도 올리기.
4. **텔레그램 봇 알림 · 일정 앞뒤 브리프**(1~2주).
5. **신뢰 장부 · 주간 정리 · 이야기 고정 주소**.

## 9. 위험과 한계(정직하게)

- 한국어 채널이 전체의 14%뿐 → '한국보다 먼저'는 "우리가 보는 한국어 채널 기준"이라고 표시하고, 국내 채널을 늘린다.
- 이야기 묶기 품질이 전부를 좌우 → 원형의 엉킴(211건) 같은 문제를 숫자로 감시(이야기 크기 분포, 사람 표본 검수).
- 로컬 Gemma 한 대가 판정과 요약을 같이 함 → 바뀐 이야기만 다시 쓰는 방식으로 부담을 낮춘다. Qwen 같은 큰 모델 병행은 메모리상 판정을 멈추게 해 쓰지 않는다.
- 원문 재게시 금지 원칙 유지 — 우리 문장과 근거 링크만.
- 야후 시세는 비공식 → 상업화 전 유료 출처.
